# 划词双向翻译与等待状态修复（1.0.2）

## 行为

选中中文译成英文，选中英文译成中文。方向在本机判断，不额外请求模型分类；判断时忽略 URL 和行内代码，比较汉字数量与英文单词数，混合文本按主要语言选择，含中文的平局偏向中译英。简繁体与 Unicode 扩展汉字均参与判断。无法按中英文识别的其他语言默认译成中文。此规则是启发式，不能保证所有短语、专有名词和混合文本都符合使用者预期。

语言判断只用于决定目标语言，不修改发送给模型的原始选中文字。实际 API 请求收到同一方向，缓存键区分 `zh-en` 和 `en-zh` 并使用新的划词版本标识；错误方向的旧缓存不会被复用。浮窗译文标签显示“中文”或“英文”。微软拼音的约 0.3 秒触发与截图翻译不作改动。

## 已定位的问题

旧版在 API 成功后、选区复核失败时以及取消路径中，缺少对“正在翻译”的终态更新。这会让已经结束的流程看起来仍在等待。另外，选区监控复核超时后仅返回 false，却保留当前选区；下一次读到相同选区时去重逻辑不再发布它，可能一直无法恢复翻译。排队的过期复核任务还可能在慢页面恢复后继续占用读取线程。

## 修复

- 完整显示确认选区、等待接口、返回后复核、完成、失败、取消与超时。所有状态受当前请求与选区版本约束，旧请求与迟到结果不覆盖新任务，也不覆盖其他功能后来更新的状态。
- 划词 API 等待上限为 20 秒，取消会传给实际请求与缓存中的共享任务；即使假提供者完全忽略取消，调用方也能结束等待。超时后不自动重发付费请求，重新划选可重试。
- 原选区监控的复核等待上限保持 2 秒；应用边界另有 3 秒的后备保护。超时撤销旧快照并允许后续读取重新发布相同文本，尚未执行的过期复核直接跳过。晚返回的旧读取不能使旧选区恢复有效。
- 请求清理异步等待取消回调，不再让异常缓慢的取消回调拖住已经完成的划词任务。保留原有前台窗口、真实文本选区和显示前复核，不用剪贴板或整页正文冒充选区。
