# Tab 自动粘贴阻断定位与修复（2026-11-05）

## 定位结论

用户反馈“所有输入框都有预览，但有些显示仅预览；有些显示 Tab 输入英文却无反应，剪贴板也无译文”。只读进程元数据确认运行的是上次提供的 `PinyinTranslate-universal-input-win-x64`，没有将问题归因于用户运行更早的版本。

代码定位及隔离对照确认了写入之前的阻断：

1. `ObserveAsync` 允许没有基线的候选显示译文，但旧 `TryAcceptTab` 要求非空且匹配的基线。点击后首键早于第一次 100ms 上下文读取、首次读取已含半段拼音、启动或同框焦点通知清空基线，均能出现预览成功却从未调用写入器的情况。
2. 客户端立即撤销候选，而失效通知异步送达；旧票据仍非空时 Tab 直接返回 false，绕过已有等待最新候选的逻辑。普通 Tab 随后清掉本轮状态。
3. 可选 ValuePattern 读取失败或与 TextPattern 投影不同，会过度收紧通用粘贴能力；没有补读可核对的 caret、局部可写属性和中文活动组合范围，也会导致“仅预览”。
4. 拒绝后的普通 Tab 会增加输入代次，异步拒因提示随之被丢弃；写入后具体 UserNotice 又可能被协调器的泛化错误覆盖，让界面看起来没有反应。

没有对用户当前真实输入框做 UIA 查询、截图或操作，所以这些是已经隔离复现并修复的程序路径，不将它们宣称为对每个实际输入框的现场诊断。

## 旧发布 Runtime 对照

`tools/HeadlessTabProbe` 将旧发布 App.dll 中的 Runtime 隔离加载，与新版使用相同的受控 Input 类型和 fake 边界。两者均不调用产品入口、构造或 Dispose；读取、取消、前台窗口、翻译和粘贴全是合成状态。新版 writer 运行真实 `VerifiedPasteWorkflow` 与基线恢复代码，不是一个永远返回成功的空桩。

场景：先捕获基线，再发生焦点通知，随后同一输入框出现新候选并按新的 Tab。

| 对照对象 | 译文已就绪 | Tab 接受 | 写入器调用 | 虚拟剪贴板准备 | 最终核对 |
| --- | --- | --- | --- | --- | --- |
| 旧发布 Runtime | 是 | 否 | 0 | 0 | 未进入 |
| 修复 Runtime | 是 | 是 | 1 | 1 | 通过，前后文字保留 |

结构化输出见 `tab-paste-comparison.json`。这说明旧版在 Tab 接受入口就退出，并非已调用系统粘贴后无效果；新版在同一可复现场景能走到实际状态机的最终核对。

## 修复行为

- 完整可写的当前候选可以接受 Tab，旧基线允许为空或仅作为假设。取消拼音后，依据实际删除的 ASCII 拼音、未变的前缀/后缀及精确光标，重建原始基线；不发送退格、不猜删原文。
- 明确 Active composition 范围允许中文预编辑和真正的组合选区；必须观察到 Inactive 且该精确范围消失，光标回到范围起点。普通非空选区不会被 caret fallback 覆盖。
- 未知覆盖式组合且取消后文本完全不变时，仍不凭候选框消失盲目粘贴，而是返回“未进入剪贴板粘贴”的具体原因。
- 候选刚失效而票据尚未清空时，有界等待同一输入位置的新候选；继续输入、鼠标、失焦、模式变化仍撤销旧请求。
- TextPattern 提供完整正文时，通用粘贴只使用该正文作为文本权威，ValuePattern 失败或投影不同会降到粘贴，不用不一致的 ValuePattern 做整框 SetValue。专用写入策略在取消前后变化时转通用流程或停止，绝不误落到 WPF Unicode 输入。
- 显示并记录 Tab 入口、取消、基线、剪贴板准备、发送粘贴、核对和恢复等阶段。拒绝说明不会被普通 Tab 透传吞掉，具体结果不会被泛化错误覆盖。

## 测试约束与范围

本轮遵守“不控制电脑测试”：没有启动产品或真实输入窗口，没有安装真实全局钩子，没有读取实时 UIA、访问系统剪贴板、发送真实按键或调用付费翻译 API。没有读取真实 API Key。

`scripts/test.ps1 -HeadlessOnly` 精确核对当前 20 份已审查测试/辅助源码，只排除可能读取外部真实凭据的一个可选测试。最终结果为 **242 项通过、0 失败**：Core 191、Selection 11、桌面逻辑 40；运行器 skipped=0，外部凭据测试在运行前精确过滤。测试包括纯 Hook 状态机、原始 Runtime 状态机、真实取消/恢复/粘贴状态机、虚拟 clipboard/keyboard、合成 composition/caret、提示队列和日志脱敏。

不保证所有应用兼容：缺少完整正文、可靠光标、明确可写状态或可证明的组合结束证据时仍会拒绝；超过 8192 UTF-16 单元的文档、高权限目标及不可靠的自绘控件仍有边界。新版在实际微软拼音和目标应用中的操作效果未在本轮验证。

## 元数据诊断

新版正式使用时，`%LOCALAPPDATA%\PinyinTranslate\logs\ime-input.jsonl` 记录阶段、常量原因码、能力布尔值和长度，约 1MB 轮转为 `ime-input.previous.jsonl`。不记录原文、译文、候选内容、密钥、AutomationId 或 RuntimeId；无桌面测试夹具不构造日志器，测试只校验静态格式输出。

检查卡点时应使用这些阶段与原因码。剪贴板没有英文不能单独证明未写入：成功粘贴会恢复原剪贴板，已验证控件也可能使用专用写入通道。
