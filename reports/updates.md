# 软件内更新

## 使用

发布源固定为公开仓库 `ihhhhhooo/trans` 的 GitHub Releases，客户端无需 GitHub 令牌，只检查稳定版的 `win-x64` 渠道。更新使用固定版本的 Velopack 1.2.161。

第一次从旧版迁移时，退出旧程序，下载 Releases 中的 `Portable.zip`，完整解压到可写目录，运行根目录 `PinyinTranslate.exe`。不要仅复制 `current` 内的主程序，也不要把更新用 `.nupkg` 当作日常安装包。旧版普通 ZIP 运行时会明确提示需要这一次手动迁移。

以后在“设置 → 软件更新”点击“检查更新”。发现新版后点击“下载更新”，可查看进度、取消和重试；下载成功并通过校验后，点击“更新并重启”。重启前需保存修改过的密钥并完成截图操作。检查和下载期间软件继续运行，不在启动时偷偷安装，不在下载完成时自动重启。

现有 `%LOCALAPPDATA%\PinyinTranslate` 中的 DPAPI 密钥、设置和用量不会随程序目录替换。程序包不包含这些本机数据。若已有明确属于本程序的已启用启动项，便携版首次启动会将其指向根目录启动器；未开启和不认识的自定义命令不改动。此策略的测试使用纯路径字符串，不访问注册表。

## 机制和故障处理

程序启动入口先处理 Velopack 生命周期参数，再创建 WPF、单实例锁、快捷键及候选服务。每一轮更新检查、下载与重启准备串行执行；重复点击不重复请求，取消或过期操作的结果不会重新启用安装。只允许下载本轮检查所得、正确包 ID、正确渠道、比当前版本新的稳定版完整包，下载交由官方 SDK 校验。

点击重启时，先禁止新输入服务绑定和截图，取消当前翻译，暂停两个模式，并等待所有本程序创建的候选桥接进程真正退出。随后重新核对未保存设置，并在根目录、当前程序目录和更新包目录以独占新文件进行写入及删除预检；预检只清理自己成功创建的临时文件，不修改权限或提权。准备或交接失败时恢复先前模式并保留当前窗口。只有准备成功，才通知官方更新程序等待本程序正常退出；随后通过 WPF 的正常关闭流程释放资源。界面只显示“正在退出并重启”，不会将交接成功冒充升级已完成。目录预检不能排除其后权限变化或其他程序占用。

网络断开、GitHub 限流、尚无发布、下载损坏或准备失败会显示可理解的状态。没有网络就不能从 GitHub 获取新版本，可稍后重试或手动下载完整便携包。程序不承诺绕过当地网络限制。更新文件由 HTTPS、固定发布仓库和官方 SDK 哈希校验保护；未配置商业代码签名证书。

## 发布

统一版本位于 `Directory.Build.props`。包 ID 为 `PinyinTranslate.Desktop`，应用标题为 `PinyinTranslate`，渠道为 `win-x64`，仅发布便携版与完整更新包。

1. 修改代码并递增三段版本号，运行 `./scripts/test.ps1 -HeadlessOnly`。
2. 提交源码并推送 `main`，推送对应的 `vX.Y.Z` 标签。
3. GitHub Actions 在 Windows runner 构建测试、打包，再以最小发布权限创建草稿，上传便携包、更新包、索引与校验清单，最后公开 Release。失败的草稿不当作有效更新。

`./scripts/package.ps1 -Velopack` 可在本机生成相同格式的产物。`./scripts/release.ps1` 默认只校验；只有显式 `-Publish` 才通过环境变量中的发布凭据发布，不将令牌作为命令行参数或打入程序包。不允许覆盖已发布版本。详细参数以脚本为准。

## 验证边界
