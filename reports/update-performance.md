# 更新性能优化（1.0.5）

## 原因与改动

固定 SDK 1.2.161 的 GitHub 发布源会先取得最近 10 条发布记录，再依次下载其中每个版本的渠道索引。当前只有最新完整包需要安装，读取旧版索引会增加串行网络等待。原下载器为每次请求新建连接处理器，失败后还会将整个 URL 转为小写再尝试，这对大小写敏感的固定 GitHub 资产没有帮助。

代码改为直接读取本仓库 `/releases/latest/download/releases.win-x64.json`：一次逻辑索引请求（HTTPS 重定向另计），每次手动检查仍重新请求，没有引入可能把新版误报成旧版的本地版本缓存。空、损坏、错误包 ID／渠道的索引会报错，不作“已经最新”处理。

下载包始终使用 `/releases/download/v<本轮版本>/<固定包名>`，不会随着 latest 指向变化而改下载别的版本。继续校验本轮令牌、版本、包名、尺寸和 SHA256，安装交接逻辑不变。

HTTP 客户端复用连接池，优先 HTTP/2 并允许 HTTP/1.1 回退；不修改系统网络代理设置或 TLS 证书校验。元数据最多等待 15 秒，超时与主动取消分开显示。对文件传输使用流式读取、128 KiB 缓冲及下载进度，连续 30 秒无新数据时结束该次读取。

本轮下载中的网络中断、截断和部分临时服务错误最多尝试 3 次。若已下载前缀有强 ETag，重试会发送 Range 与 If-Range，并检查 206 的起点、长度和 ETag；服务器返回完整 200 时重新写入，防止拼接不同内容。没有强校验器或只有弱 ETag 时重新下载。权限、404、429 等错误不重复请求，也不将 URL 改为小写。主动取消不重试。

这是同一次下载操作内的恢复，不承诺退出软件或点击取消后保留下载断点。当前 SDK 会在下一轮下载前清理自己的临时文件。流传输完成的 100% 只代表“开始校验”，只有 SDK 成功返回才允许安装。

## 性能边界

完整更新包约 75.5 MiB，仍包含自带运行时；此轮没有改变发行格式或启用差分包。连接复用和恢复减少网络往返与失败重传，但不能承诺 GitHub 在所有网络下达到固定速度。更小的差分包需要另行实现发布端基线与差分生成、验证、回退等配套工作。

验证使用注入的假 HTTP、合成断流／卡住的响应、临时测试文件及假生命周期，没有构造真实 UpdateManager、运行安装程序或更新重启，也没有操作桌面或系统剪贴板。另可运行只读公开索引探针验证实际最新源；这类测量只涵盖索引读取，不代表按钮整体耗时或所有网络环境。

## 验证结果

2026-11-06 运行 `./scripts/test.ps1 -HeadlessOnly`：Core 332、Selection 108、Screenshot/App 118、Update 77，共 **635 项通过，0 失败、0 跳过**。读取真实外部凭据的可选测试仍在执行前排除。更新相关测试覆盖固定版本下载、索引错误拒绝、条件断点续传、弱／无 ETag 回退、实体变化重下、错误 Range 拒绝、永久错误与限流不重试、截断／卡住后的有界重试、取消，以及校验结束前不能安装。另验证最后一个字节仍未到达时，不会因为 SDK 的偶数进度取整而提前显示下载完成。

只读公开索引探针的单次样本：新路径 1 次索引请求，3646 ms；原 SDK 历史遍历路径 6 次元数据请求，5 个资产，5415 ms。两种路径使用同一个新版传输器，仅用于对比索引遍历，未构造安装定位器或 UpdateManager。结果受缓存、连接状态和网络影响，不代表所有用户或按钮完整耗时。

已下载的 1.0.4 完整包为 79,139,444 字节（75.47 MiB），单独读取文件计算 SHA256 的本次样本为 373 ms，与已发布哈希一致。这不是整个 SDK 校验、磁盘／杀毒扫描及更新程序准备阶段的总耗时，也没有测量新下载器的真实大文件吞吐。
